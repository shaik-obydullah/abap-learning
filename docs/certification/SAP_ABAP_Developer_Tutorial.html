1. Introduction to SAP ABAP

ABAP (Advanced Business Application Programming) is SAP's proprietary programming language used to develop business applications on the SAP platform. It runs on the SAP NetWeaver Application Server and powers everything from simple reports to complex enterprise solutions.

Key Concepts

ConceptDescriptionT-Code
ABAP DictionaryCentral metadata repository for tables, views, typesSE11
ProgramsExecutable code units (reports, includes, module pools)SE38
IncludesReusable code fragments for program modularizationSE38
Function ModulesReusable function blocks (encapsulated logic)SE37
ClassesObject-oriented programming unitsSE24
ScreensUI elements (selection screens, dynpros)SE51

How to Access the ABAP Editor

  • Transaction Code: SE38 — ABAP Editor
  • Transaction Code: SE80 — Object Navigator
Note: All program names you create should start with Z or Y to avoid conflicts with SAP standard objects. This is a strict naming convention in SAP systems.

2. Hello World Program

Step 1: Create a New Program

  1. Open Transaction SE38
  2. Enter program name: ZHELLO_WORLD
  3. Click Create
  4. Select type: Executable Program
  5. Enter a title and save

Step 2: Write the Code

REPORT zhello_world.

WRITE: 'Hello, World!'.
WRITE: / 'Welcome to SAP ABAP Development'.

Step 3: Execute

Press F8 or click the Execute button.

Expected Output

Hello, World!
Welcome to SAP ABAP Development
Tip: The / is a write-cursor control — it moves to a new line before writing. This is essential for proper list output formatting.

Understanding the WRITE Statement

StatementEffect
WRITE value.Writes value at current cursor position
WRITE / value.Moves to new line, then writes
WRITE: / a, b, c.Colon notation for chaining multiple writes
ULINE.Draws a horizontal line
SKIP n.Skips n empty lines
FORMAT COLOR COL_TOTAL.Sets output formatting

4. Control Structures

IF...ELSEIF...ELSE...ENDIF

DATA: lv_grade TYPE c LENGTH 1,
      lv_score TYPE i VALUE 85.

IF lv_score >= 90.
  lv_grade = 'A'.
ELSEIF lv_score >= 80.
  lv_grade = 'B'.
ELSEIF lv_score >= 70.
  lv_grade = 'C'.
ELSE.
  lv_grade = 'F'.
ENDIF.

WRITE: / 'Score:', lv_score.
WRITE: / 'Grade:', lv_grade.
Boolean Operators: AND, OR, NOT can be combined: IF a = 1 AND b = 2 OR c <> 3.

CASE...ENDCASE

DATA: lv_day       TYPE i VALUE 3,
      lv_day_name TYPE string.

CASE lv_day.
  WHEN 1.
    lv_day_name = 'Monday'.
  WHEN 2.
    lv_day_name = 'Tuesday'.
  WHEN 3.
    lv_day_name = 'Wednesday'.
  WHEN OTHERS.
    lv_day_name = 'Other Day'.
ENDCASE.

DO...ENDDO Loop

DATA: lv_count TYPE i VALUE 1.

DO 5 TIMES.                       " Fixed iterations
  WRITE: / 'Iteration:', sy-index.   " sy-index is the loop counter
ENDDO.

* --- Infinite loop with EXIT ---
DO.
  lv_count = lv_count + 1.
  IF lv_count > 10.
    EXIT.                            " Leave the loop
  ENDIF.
ENDDO.

* --- CONTINUE skips one iteration ---
DO 5 TIMES.
  IF sy-index = 3.
    CONTINUE.
  ENDIF.
  WRITE: / 'Value:', sy-index.
ENDDO.

WHILE...ENDWHILE

DATA: lv_counter TYPE i VALUE 1.

WHILE lv_counter <= 10.
  WRITE: / 'Counter:', lv_counter.
  lv_counter = lv_counter + 1.
ENDWHILE.

5. Internal Tables

Internal tables are the most important data structure in ABAP. They are runtime objects that store multiple data records in memory.

Types of Internal Tables

TypeAccess TypeUse Case
Standard TableIndex (sequential scan)Default; flexible, fast for APPEND
Sorted TableBinary search on keySorted by key; faster READ with key
Hashed TableHash on unique keyVery fast lookups by key, no indexing
Index TableGeneric index accessAbstract type for standard/sorted

Defining Structures & Tables

* --- Define a flat structure ---
TYPES: BEGIN OF ty_employee,
         emp_id     TYPE i,
         name       TYPE string,
         department TYPE string,
         salary     TYPE p LENGTH 8 DECIMALS 2,
       END OF ty_employee.

* --- Declare work area + internal table ---
DATA: lt_employees TYPE STANDARD TABLE OF ty_employee,
      ls_employee  TYPE ty_employee.

Core Operations

* ============ INSERT ============
ls_employee-emp_id = 1001.
ls_employee-name = 'Alice Johnson'.
ls_employee-department = 'IT'.
ls_employee-salary = 75000.
APPEND ls_employee TO lt_employees.       " Append to end

INSERT ls_employee INTO lt_employees INDEX 1.  " Insert at position 1
INSERT ls_employee INTO TABLE lt_employees.       " Insert sorted (for sorted tables)

* ============ READ ============
READ TABLE lt_employees INTO ls_employee
  WITH KEY emp_id = 1002.
IF sy-subrc = 0.                        " 0 = record found
  WRITE: / 'Found:', ls_employee-name.
ENDIF.

* ============ LOOP (sequential processing) ============
LOOP AT lt_employees INTO ls_employee.
  WRITE: / ls_employee-emp_id, ls_employee-name,
           ls_employee-department, ls_employee-salary.
ENDLOOP.

* ============ SORT ============
SORT lt_employees BY salary DESCENDING.

* ============ MODIFY (update) ============
LOOP AT lt_employees INTO ls_employee WHERE department = 'IT'.
  ls_employee-salary = ls_employee-salary * 1.10.   " 10% raise
  MODIFY lt_employees FROM ls_employee.
ENDLOOP.

* ============ DELETE ============
DELETE lt_employees WHERE emp_id = 1002.

* ============ DESCRIBE ============
DATA: lv_lines TYPE i.
DESCRIBE TABLE lt_employees LINES lv_lines.
WRITE: / 'Total Employees:', lv_lines.

* ============ CLEAR / REFRESH / FREE ============
CLEAR  lt_employees.     " Removes content on CURRENT line (for tables: header line only)
REFRESH lt_employees.   " Removes all lines
FREE   lt_employees.     " Frees memory immediately
Important: Always check sy-subrc after READ TABLE, APPEND, DELETE, and MODIFY. A non-zero return code means the operation did not find the target.

Field Symbols (Performance)

* --- Field symbols avoid copying data (faster) ---
FIELD-SYMBOLS: <fs_emp> LIKE ls_employee.

LOOP AT lt_employees ASSIGNING <fs_emp>.
  <fs_emp>-salary = <fs_emp>-salary * 1.05.  " Direct modification
ENDLOOP.
Why field symbols? LOOP AT ... INTO copies each line into a work area (memory + time cost). ASSIGNING works on the line directly — recommended for large data volumes.

6. Modularization

Modularization keeps your code clean, reusable, and maintainable. ABAP offers three main techniques:

Subroutines (FORM...PERFORM)

REPORT zmodularization.

* --- Call the subroutines ---
PERFORM display_header.
PERFORM calculate_area USING 10 5.   " Pass values by reference

DATA: ls_employee TYPE ty_employee.
PERFORM get_employee_info CHANGING ls_employee.

* ============================================
* Subroutine definitions (usually in a form include)
* ============================================
FORM display_header.
  WRITE: / '================================'.
  WRITE: / '     EMPLOYEE REPORT'.
  WRITE: / '================================'.
ENDFORM.

FORM calculate_area USING iv_length TYPE i
                           iv_width  TYPE i.
  DATA: lv_area TYPE i.
  lv_area = iv_length * iv_width.
  WRITE: / 'Area:', lv_area.
ENDFORM.

FORM get_employee_info CHANGING cs_employee TYPE ty_employee.
  cs_employee-emp_id = 1001.
  cs_employee-name   = 'John Doe'.
ENDFORM.
Parameter TypeKeywordBehavior
Input (passing value)USING / VALUE()Caller can't be changed
Output (return value)CHANGING / VALUE()Callee can change caller variable
Both (by reference)USING (default)Changes propagate to caller

Function Modules

Function modules are reusable, centrally stored wherever in the system (domain RF).

DATA: lv_result TYPE p LENGTH 8 DECIMALS 2.

CALL FUNCTION 'CONVERT_TO_LOCAL_CURRENCY'
  EXPORTING
    date             = sy-datum
    foreign_amount   = 1000
    foreign_currency = 'USD'
  IMPORTING
    exchange_rate    = lv_result
  EXCEPTIONS
    no_rate_found    = 1
    overflow         = 2
    OTHERS           = 99.

IF sy-subrc = 0.
  WRITE: / 'Exchange Rate:', lv_result.
ELSE.
  WRITE: / 'Conversion failed'.
ENDIF.

Object-Oriented Classes

REPORT zoo_concepts.

* --- Local class definition ---
CLASS lcl_vehicle DEFINITION.
  PUBLIC SECTION.
    METHODS: set_make    IMPORTING iv_make  TYPE string,
              set_model   IMPORTING iv_model TYPE string,
              display_info.
  PRIVATE SECTION.
    DATA: mv_make  TYPE string,
          mv_model TYPE string.
ENDCLASS.

CLASS lcl_vehicle IMPLEMENTATION.
  METHOD set_make.
    mv_make = iv_make.
  ENDMETHOD.

  METHOD set_model.
    mv_model = iv_model.
  ENDMETHOD.

  METHOD display_info.
    WRITE: / 'Make:',  mv_make.
    WRITE: / 'Model:', mv_model.
  ENDMETHOD.
ENDCLASS.

* --- Usage ---
DATA: lo_vehicle TYPE REF TO lcl_vehicle.

CREATE OBJECT lo_vehicle.                    " Instantiates the object
lo_vehicle->set_make( 'Toyota' ).        " Method call (functional style)
lo_vehicle->set_model( 'Camry' ).
lo_vehicle->display_info( ).

Inheritance & Interfaces

CLASS lcl_vehicle DEFINITION.
  PUBLIC SECTION.
    METHODS: start_engine.
  PROTECTED SECTION.  " Accessible by this class AND subclasses
    DATA: mv_fuel TYPE i.
ENDCLASS.

CLASS lcl_car DEFINITION INHERITING FROM lcl_vehicle.
  PUBLIC SECTION.
    METHODS: set_doors IMPORTING iv_doors TYPE i.
  PRIVATE SECTION.
    DATA: mv_doors TYPE i.
ENDCLASS.

* --- Call inherited method on the subclass ---
DATA: lo_car TYPE REF TO lcl_car.
CREATE OBJECT lo_car.
lo_car->start_engine( ).          " Inherited from parent
Visibility Sections: PUBLIC — accessible everywhere; PROTECTED — class + subclasses; PRIVATE — only this class.

7. Database Operations (Open SQL)

Open SQL gives you a database-independent way to read and modify data. Imagine you work with SAP flight demo tables (sflight, spfli, scarr) when learning.

SELECT (Read Data)

DATA: ls_sflight  TYPE sflight,             " Use dictionary structure directly
      lt_sflights TYPE STANDARD TABLE OF sflight.

* --- Single record ---
SELECT SINGLE carrid connid fldate seatsmax seatsocc
  INTO ls_sflight
  FROM sflight
  WHERE carrid = 'LH'.
IF sy-subrc = 0.
  WRITE: / ls_sflight-carrid, ls_sflight-connid, ls_sflight-fldate.
ENDIF.

* --- Multiple records ---
SELECT carrid connid fldate seatsmax seatsocc
  INTO TABLE lt_sflights
  FROM sflight
  WHERE carrid = 'LH'
  ORDER BY connid.                 " Sorted ascending

* --- Aggregate functions ---
DATA: lv_count TYPE i,
      lv_avg   TYPE p LENGTH 8 DECIMALS 2.

SELECT COUNT(*) FROM sflight INTO lv_count.
SELECT AVG( seatsocc ) FROM sflight INTO lv_avg.
SELECT MAX( seatsmax ) FROM sflight INTO lv_count.
Performance Rule #1: Use SELECT ... INTO TABLE (single round-trip) instead of SELECT ... INTO in a LOOP/ENDSELECT (many round-trips). Only avoid bundling for very large result sets.

INSERT (Add Data)

DATA: ls_spfli TYPE spfli.

ls_spfli-carrid    = 'XY'.
ls_spfli-connid    = '0001'.
ls_spfli-cityfrom  = 'NEW YORK'.
ls_spfli-cityto    = 'LOS ANGELES'.

INSERT INTO spfli VALUES ls_spfli.
IF sy-subrc = 0.
  WRITE: / 'Record inserted successfully'.
ELSE.
  WRITE: / 'Insert failed - duplicate key?'.
ENDIF.

UPDATE (Change Existing Data)

UPDATE spfli SET cityfrom = 'CHICAGO'
  WHERE carrid = 'XY' AND connid = '0001'.

IF sy-subrc = 0.
  WRITE: / 'Record updated successfully'.
ENDIF.

MODIFY (Insert or Update)

MODIFY spfli FROM ls_spfli.
" Inserts if key does not exist; updates if it exists (one statement)

DELETE (Remove Data)

DELETE FROM spfli WHERE carrid = 'XY' AND connid = '0001'.
IF sy-subrc = 0.
  WRITE: / 'Record deleted successfully'.
ENDIF.

Transaction Control

COMMIT WORK.    " Permanently saves DB changes
ROLLBACK WORK.  " Undoes all changes since last COMMIT

FOR ALL ENTRIES (Join Alternative)

* --- Get a list of airline codes ---
DATA: lt_carrids TYPE STANDARD TABLE OF s_carr_id.
APPEND 'LH' TO lt_carrids.
APPEND 'UA' TO lt_carrids.

IF lt_carrids IS NOT INITIAL.
  SELECT carrid connid fldate
    INTO TABLE lt_sflights
    FROM sflight
    FOR ALL ENTRIES IN lt_carrids
    WHERE carrid = lt_carrids-table_line.
  " IMPORTANT: clear source table before LOOP, or it may return duplicates
ENDIF.
Gotcha: With FOR ALL ENTRIES, always check the source table is not empty, and mind that records with fully-empty keys are ignored (the DB may return duplicates).

8. Selection Screens

Selection screens let users enter parameters before running a report. They are automatically generated from PARAMETERS and SELECT-OPTIONS declarations.

Basic Selection Screen

REPORT zselection_screen.

* --- Parameters (single value inputs) ---
PARAMETERS: p_carrid TYPE s_carr_id OBLIGATORY,        " Mandatory field
            p_connid TYPE s_conn_id,
            p_date   TYPE s_date DEFAULT sy-datum,   " Default value
            p_show   TYPE abap_bool AS CHECKBOX DEFAULT 'X'.

* --- Select-options (range inputs) ---
SELECT-OPTIONS: s_fldate FOR sflight-fldate,
                s_city   FOR sflight-cityfrom.

* --- Event: set defaults at program start ---
INITIALIZATION.
  p_carrid = 'LH'.

* --- Event: validate input ---
AT SELECTION-SCREEN.
  IF p_carrid IS INITIAL.
    MESSAGE 'Please enter a carrier ID' TYPE 'E'.  " Error stops execution
  ENDIF.

* --- Product output ---
START-OF-SELECTION.
  WRITE: / 'Carrier:', p_carrid.
  WRITE: / 'Connection:', p_connid.
  WRITE: / 'Date:', p_date.
  IF p_show = 'X'.
    WRITE: / 'Show details enabled'.
  ENDIF.

Listbox and Value Help

INITIALIZATION.
  DATA: lt_values TYPE vrm_values,
        ls_value  TYPE vrm_value.

  ls_value-key = 'O'.   ls_value-text = 'Open'.
  APPEND ls_value TO lt_values.
  ls_value-key = 'C'.   ls_value-text = 'Closed'.
  APPEND ls_value TO lt_values.
  ls_value-key = 'X'.   ls_value-text = 'Cancelled'.

Tip: SELECT-OPTIONS creates an internal table with fields sign, option, low, high. You can use it directly in IN in your WHERE clause.

9. ALV Reports

ALV (ABAP List Viewer) is SAP's standard grid/table output control. It provides interactive features like sorting, filtering, totals, and export out-of-the-box.

Simple ALV Report (CL_SALV_TABLE)

REPORT zsimple_alv.

TYPES: BEGIN OF ty_sflight,
         carrid   TYPE s_carr_id,
         connid   TYPE s_conn_id,
         fldate   TYPE s_date,
         price    TYPE s_price,
         currency TYPE s_currcode,
         seatsmax TYPE s_seatsmax,
         seatsocc TYPE s_seatsocc,
       END OF ty_sflight.

DATA: lt_sflight TYPE STANDARD TABLE OF ty_sflight,
      lo_alv    TYPE REF TO cl_salv_table,
      lx_msg    TYPE REF TO cx_salv_msg.

SELECT carrid connid fldate price currency seatsmax seatsocc
  INTO TABLE lt_sflight
  FROM sflight.

TRY.
    cl_salv_table=>factory(
      IMPORTING r_salv_table = lo_alv
      CHANGING  t_table      = lt_sflight ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO lx_msg.
    WRITE: / 'Error:', lx_msg->get_text( ).
ENDTRY.

ALV with Layout, Colors & Totals

TRY.
    cl_salv_table=>factory(
      IMPORTING r_salv_table = lo_alv
      CHANGING  t_table      = lt_flights ).

    * --- Display settings ---
    DATA: lo_display TYPE REF TO cl_salv_display_settings.
    lo_display = lo_alv->get_display_settings( ).
    lo_display->set_striped_pattern( abap_true ).
    lo_display->set_list_header( 'Flight List' ).
    lo_display->set_horizontal_lines( abap_true ).

    * --- Activate all standard functions (export, layouts, etc.) ---
    DATA: lo_funcs TYPE REF TO cl_salv_functions_list.
    lo_funcs = lo_alv->get_functions( ).
    lo_funcs->set_all( abap_true ).

    * --- Column handling ---
    DATA: lo_columns TYPE REF TO cl_salv_columns_table,
          lo_column  TYPE REF TO cl_salv_column.
    lo_columns = lo_alv->get_columns( ).
    lo_columns->set_optimize( abap_true ).

    TRY.
        lo_column = lo_columns->get_column( 'CURRENCY' ).
        lo_column->set_visible( abap_false ).        " Hide column

        lo_column = lo_columns->get_column( 'CARRID' ).
        lo_column->set_long_text( 'Airline' ).
        lo_column->set_medium_text( 'Airline Code' ).
      CATCH cx_salv_not_found.
    ENDTRY.

    * --- Aggregations (totals) ---
    lo_alv->get_aggregations( )->add_aggregation(
      columnname  = 'PRICE'
      aggregation = if_salv_c_aggregation=>total ).

    * --- Sorting ---
    lo_alv->get_sorts( )->add_sort( 'CARRID' ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO lx_msg.
    WRITE: / 'Error:', lx_msg->get_text( ).
ENDTRY.

ALV Events (Double-click)

CLASS lcl_alv_handler DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS: on_double_click
      FOR EVENT double_click OF cl_salv_events_table
      IMPORTING row column.
ENDCLASS.

CLASS lcl_alv_handler IMPLEMENTATION.
  METHOD on_double_click.
    DATA: ls_flight TYPE ty_flight.
    READ TABLE lt_flights INTO ls_flight INDEX row.
    IF sy-subrc = 0.
      WRITE: / 'Clicked row:', row,
               'Flight:',  ls_flight-carrid, ls_flight-connid.
    ENDIF.
  ENDMETHOD.
ENDCLASS.

* --- Register the handler ---
DATA: lo_events TYPE REF TO cl_salv_events_table.
lo_events = lo_alv->get_event( ).
SET HANDLER lcl_alv_handler=>on_double_click FOR lo_events.
lo_alv->display( ).
Two ALV families: The modern cl_salv_table (OO) and the older REUSE_ALV_GRID_DISPLAY (FM-based) with i_callback_program/i_callback_user_command. Prefer the OO family for new development.

10. Custom Report Development

This is a complete "real-world" order report. It puts everything together: selection screen, database reads, business logic, and ALV output.

REPORT zcustom_report MESSAGE-ID zmsg.

* ==================================================
* Type definitions
* ==================================================
TYPES: BEGIN OF ty_order,
         order_id      TYPE c LENGTH 10,
         customer_id   TYPE c LENGTH 10,
         customer_name TYPE string,
         order_date    TYPE d,
         amount        TYPE p LENGTH 10 DECIMALS 2,
         status        TYPE c LENGTH 1,
       END OF ty_order.

* ==================================================
* Global data
* ==================================================
DATA: gt_orders TYPE STANDARD TABLE OF ty_order,
      gs_order  TYPE ty_order,
      go_alv    TYPE REF TO cl_salv_table,
      gx_msg    TYPE REF TO cx_salv_msg.

* ==================================================
* Selection screen
* ==================================================
SELECTION-SCREEN BEGIN OF BLOCK b1 WITH FRAME TITLE text-001.
  SELECT-OPTIONS: s_coid FOR gs_order-order_id,
                  s_cust FOR gs_order-customer_id,
                  s_date FOR gs_order-order_date.
  PARAMETERS:     p_stat AS LISTBOX VISIBLE LENGTH 20
                        USER-COMMAND u1.
SELECTION-SCREEN END OF BLOCK b1.

* ==================================================
* Initialization
* ==================================================
INITIALIZATION.
  " Default date range: last 30 days
  s_date-low  = sy-datum - 30.
  s_date-high = sy-datum.
  APPEND s_date.

  " Fill the status Listbox
  DATA: lt_values TYPE vrm_values,
        ls_value  TYPE vrm_value.
  ls_value-key = 'O'.  ls_value-text = 'Open'.
  APPEND ls_value TO lt_values.
  ls_value-key = 'C'.  ls_value-text = 'Closed'.
  APPEND ls_value TO lt_values.
  ls_value-key = 'X'.  ls_value-text = 'Cancelled'.
  APPEND ls_value TO lt_values.

  CALL FUNCTION 'VRM_SET_VALUES'
    EXPORTING id     = 'P_STAT'
               values = lt_values.

* ==================================================
* Validation
* ==================================================
AT SELECTION-SCREEN.
  IF s_coid[] IS INITIAL AND s_cust[] IS INITIAL.
    MESSAGE e001 WITH 'Enter Order ID or Customer ID'.
  ENDIF.

* ==================================================
* Main flow
* ==================================================
START-OF-SELECTION.
  PERFORM fetch_data.
  PERFORM process_data.
  PERFORM display_alv.

* --------------------------------------------------
* Fetch data
* --------------------------------------------------
FORM fetch_data.
  SELECT order_id customer_id customer_name order_date amount status
    INTO TABLE gt_orders
    FROM zorders
    WHERE order_id    IN s_coid
      AND customer_id IN s_cust
      AND order_date  IN s_date
      AND status      =  p_stat.

  IF gt_orders IS INITIAL.
    MESSAGE i002 WITH 'No data for selection' TYPE 'I'.
    LEAVE LIST-PROCESSING.     " Returns to selection screen
  ENDIF.
ENDFORM.

* --------------------------------------------------
* Business logic
* --------------------------------------------------
FORM process_data.
  DATA: ls_order TYPE ty_order.

  LOOP AT gt_orders INTO ls_order.
    CASE ls_order-status.
      WHEN 'C'.                     " Closed orders: 5% discount
        ls_order-amount = ls_order-amount * 0.95.
      WHEN 'X'.                     " Cancelled: amount zeroed
        ls_order-amount = 0.
    ENDCASE.

    MODIFY gt_orders FROM ls_order.
  ENDLOOP.

  SORT gt_orders BY order_date DESCENDING.
ENDFORM.

* --------------------------------------------------
* Display ALV
* --------------------------------------------------
FORM display_alv.
  TRY.
      cl_salv_table=>factory(
        IMPORTING r_salv_table = go_alv
        CHANGING  t_table      = gt_orders ).

      PERFORM configure_alv.
      go_alv->display( ).

    CATCH cx_salv_msg INTO gx_msg.
      MESSAGE gx_msg->get_text( ) TYPE 'E'.
  ENDTRY.
ENDFORM.

* Configure ALV settings
* --------------------------------------------------
FORM configure_alv.
  DATA: lo_display TYPE REF TO cl_salv_display_settings,
        lo_columns TYPE REF TO cl_salv_columns_table,
        lo_column  TYPE REF TO cl_salv_column,
        lo_funcs   TYPE REF TO cl_salv_functions_list,
        lo_agg     TYPE REF TO cl_salv_aggregations,
        lo_sorts   TYPE REF TO cl_salv_sorts_table.

  lo_display = go_alv->get_display_settings( ).
  lo_display->set_striped_pattern( abap_true ).
  lo_display->set_list_header( 'Custom Order Report' ).
  lo_display->set_horizontal_lines( abap_true ).

  lo_funcs = go_alv->get_functions( ).
  lo_funcs->set_all( abap_true ).

  lo_columns = go_alv->get_columns( ).
  lo_columns->set_optimize( abap_true ).

  TRY.
      lo_column = lo_columns->get_column( 'ORDER_ID' ).
      lo_column->set_long_text( 'Order Number' ).

      lo_column = lo_columns->get_column( 'AMOUNT' ).
      lo_column->set_long_text( 'Order Amount' ).
    CATCH cx_salv_not_found.
  ENDTRY.

  TRY.
      lo_agg = go_alv->get_aggregations( ).
      lo_agg->add_aggregation(
        columnname  = 'AMOUNT'
        aggregation = if_salv_c_aggregation=>total ).
    CATCH cx_salv_data_error cx_salv_not_found cx_salv_existing.
  ENDTRY.

  TRY.
      lo_sorts = go_alv->get_sorts( ).
      lo_sorts->add_sort( 'ORDER_DATE' ).
    CATCH cx_salv_not_found cx_salv_existing cx_salv_data_error.
  ENDTRY.
ENDFORM.

11. Real-Life Case Studies

These scenarios are based on issues ABAP developers face every day in production. Each case shows the problem, root cause analysis, and a working solution.

Case Study 1: Report Is Extremely Slow

Problem: A daily sales report that used to take 1 minute now takes 35 minutes. Users are complaining, and the job regularly runs over its scheduled window.

Root Cause Analysis: The most common culprit in ABAP is selecting inside a loop. When you fetch parent records and then run a new DB read for every single row, the database receives thousands of round-trips.

Anti-pattern — N+1 query problem:
SELECT vbak vbeln kunnr erdat
  INTO TABLE lt_vbak
  FROM vbak.

LOOP AT lt_vbak INTO ls_vbak.
  SELECT SINGLE kunnr name1
    INTO (lv_kunnr, lv_name1)
    FROM kna1
    WHERE kunnr = ls_vbak-kunnr.   " DB hit per row!
  ls_vbak-kname = lv_name1.
  MODIFY lt_vbak FROM ls_vbak.
ENDLOOP.

Solution — Single query with join / secondary read:

* Option A: JOIN removes the loop entirely
SELECT a~vbeln a~kunnr a~erdat b~name1
  INTO TABLE lt_result
  FROM vbak AS a
  INNER JOIN kna1 AS b ON b~kunnr = a~kunnr.

* Option B: one extra SELECT with FOR ALL ENTRIES
IF lt_vbak IS NOT INITIAL.
  SELECT kunnr name1
    INTO TABLE lt_kna1
    FROM kna1
    FOR ALL ENTRIES IN lt_vbak
    WHERE kunnr = lt_vbak-kunnr.

  LOOP AT lt_vbak ASSIGNING <fs>.
    READ TABLE lt_kna1 INTO ls_kna1
      WITH KEY kunnr = <fs>-kunnr.
    IF sy-subrc = 0.
      <fs>-kname = ls_kna1-name1.
    ENDIF.
  ENDLOOP.
ENDIF.
BeforeAfter
1 parent + 10,000 child DB calls = 10,001 round-trips2 DB calls total (JOIN / secondary read in memory)
~35 minutes wall-clock~8 seconds
Key lesson: Every DB statement behind a loop is a suspect. First rule of ABAP performance: badge of honor is to never write DB access inside a loop.

Case Study 2: ALV Grid Shows Blanks / Wrong Values for Certain Rows

Problem: In an ALV report for material movements, some rows display empty cells even though the data exists. Values get overwritten between rows.

Root Cause Analysis: The program reuses one work area in a LOOP ... INTO and appends it. ABAP work areas are not cleared automatically, so leftover values from the previous iteration leak into the next row — and APPEND copies the work area by value, making the "wrong" state appear to persist.

Classic bug:
DATA: ls_mkpf LIKE LINE OF lt_mkpf.

SELECT mblnr mjahr bwart btart
  INTO ls_mkpf                    " Work area reused, not cleared!
  FROM mkpf UP TO 100 ROWS.
  APPEND ls_mkpf TO lt_mkpf.
ENDSELECT.

Solution — always bundle INTO TABLE, and clear work areas between uses:

SELECT mblnr mjahr bwart btart
  INTO TABLE lt_mkpf          " Structure memory managed for you
  FROM mkpf.

LOOP AT lt_mkpf INTO ls_mkpf.
  CLEAR ls_msku.               " Clear BEFORE filling partial fields
  SELECT SINGLE matnr INTO ls_msku-matnr FROM msku WHERE mblnr = ls_mkpf-mblnr.
  APPEND ls_msku TO lt_msku.
ENDLOOP.
Key lesson: SELECT ... INTO TABLE removes the whole class of "dirty work area" bugs. When you must append in a loop, CLEAR first.

Case Study 3: Selection Screen Validation Rejects Valid Dates

Problem: End users enter a date range like 01.01.2025 to 31.12.2025 single values per field, but one field is a SELECT-OPTION with an empty high value. The custom check low > high fires and blocks legitimate entries.

Root Cause Analysis: Inside AT SELECTION-SCREEN, SELECT-OPTIONS fields behave differently: with a single value, high is blank and option is EQ. The validator compared the blank HIGH against LOW and thought it was an inverted range.

Flawed validation:
AT SELECTION-SCREEN.
  IF s_date-low > s_date-high.          " FAILS for single-value entries!
    MESSAGE 'Start date must be before end date' TYPE 'E'.
  ENDIF.

Solution — loop the range lines correctly:

AT SELECTION-SCREEN.
  DATA: ls_range LIKE LINE OF s_date.

  LOOP AT s_date INTO ls_range.
    CASE ls_range-option.
      WHEN 'BT' OR 'NB'.          " Range: both low & high expected
        IF ls_range-high < ls_range-low.
          MESSAGE e000 WITH 'Inverted date range'.
        ENDIF.
      WHEN 'EQ'.                    " Single value: ignore high
        " fine
    ENDCASE.
  ENDLOOP.
Key lesson: Selection-option lines are structures with SIGN/OPTION/LOW/HIGH. Validate per option type, not on raw fields.

Case Study 4: Update "Works" But Data Never Appears in the Table

Problem: A background job updates a custom table (zorders), the job finishes green, but users never see the changed rows. Re-running shows the old values again.

Root Cause Analysis: The update was executed, but the job rolled back at the end — usually because a later statement failed and the program ended with MESSAGE TYPE 'A' or an unhandled exception. In ABAP, DB changes are buffered until COMMIT WORK; an implicit rollback discards them. Another classic cause: a SELECT with a wrong key found a stale saplzms row, or the program used UPDATE ... FROM ls where ls had an empty key field.

Likely failure:
UPDATE zorders FROM ls_order.   " ls_order-key field EMPTY
IF sy-subrc <> 0.
  MESSAGE 'Nothing updated' TYPE 'E'.  " Message E stops or rolls back
ENDIF.

Solution — fill the key, use WHERE, check return code, commit explicitly:

DATA: lv_upd TYPE i.

UPDATE zorders SET status = 'C'
  WHERE order_id = ls_order-order_id.

lv_upd = sy-dbcnt.                      " Rows actually changed
IF lv_upd = 0.
  WRITE: / 'No matching row found'.
ELSE.
  COMMIT WORK.                        " Make it permanent
  WRITE: / lv_upd, 'row(s) updated'.
ENDIF.
Key lesson: Check sy-subrc, check sy-dbcnt, then COMMIT WORK. Never assume success from a green job log.

Case Study 5: Numbers and Dates Display Wrong (Packed Overflow / Date Format)

Problem: A report shows negative amounts as *-* or abbreviations like 1,000E+4, and dates appear as 20250101 instead of 01.01.2025.

Root Cause Analysis: The output column was declared as TYPE i (4-byte integer) for a value that exceeds ~2 billion, or the packed field had too few decimals. Dates are plain 8-character fields; without an output profile they render in raw format.

Broken declarations & output:
DATA: lv_total TYPE i.          " Integer overflow risk
lv_total = 5000000000.               " > 2^31-1 → dump / *-*

WRITE: / lv_total, lv_date.        " Renders raw

Solution — proper types and formatting options:

DATA: lv_total TYPE p LENGTH 15 DECIMALS 2,  " big & precise
      lv_date  TYPE d VALUE '20250101'.

lv_total = 5000000000.

WRITE: / lv_total CURRENCY 'USD'.   " Amount with currency formatting
WRITE: / lv_date DD/MM/YYYY.         " Date output mask
WRITE: / lv_total USING EDIT MASK '___.___.__0,00'.
Write OptionEffect
CURRENCY 'USD'Adds currency symbol & ISO placement
DD/MM/YYYYDate in European format
USING EDIT MASKCustom picture string
NO-ZEROSuppresses leading zeros
EXPONENT 4Controls scientific notation
Key lesson: Size your types to the domain (money → packed, never integer). Formatting belongs in the output statement, not in the data.

Case Study 6: Excel Upload Reads Only the First Column

Problem: A user uploads an Excel file with 10 columns but only column A comes through. Everything looks correct in the code.

Root Cause Analysis: The most common cause is using GUI_UPLOAD with a wrong file type (e.g., trying to read a real .xlsx as a tab-delimited text, or the file being blocked locally). Second: the structure's field order doesn't match the Excel column order. Third: the file is a binary OLE2 file but you passed filetype = 'ASC'.

Solution — use the ALSM upload for real Excel files, with a structure check:

DATA: lt_data TYPE TABLE OF alsmex_tabline.  " Generic line: col1...col40

CALL FUNCTION 'ALSM_EXCEL_TO_INTERNAL_TABLE'
  EXPORTING
    filename                = p_file
    i_begin_col             = 1
    i_begin_row             = 2        " Skip header row
    i_end_col               = 10
    i_end_row               = 10000
  TABLES
    intern                  = lt_data
  EXCEPTIONS
    inconsistent_parameters = 1
    upload_ole              = 2
    OTHERS                 = 3.

IF sy-subrc <> 0.
  MESSAGE 'Upload failed' TYPE 'E'.
ENDIF.

* Map columns by POSITION and validate
LOOP AT lt_data INTO ls_data.
  CASE ls_data-col.
    WHEN 1.  ls_mapping-order_id = ls_data-value.
    WHEN 2.  ls_mapping-amount   = ls_data-value.
  ENDCASE.
ENDLOOP.

Alternative — validate before processing: check the file format, verify the first row is the expected header, and count the number of columns; reject the file with a clear message when they don't match.

Key lesson: Match the upload function to the real file format. ALSM_EXCEL_TO_INTERNAL_TABLE handles true Excel (OLE/XML), GUI_UPLOAD is for delimited text.

Case Study 7: "Something Changed Last Week" — Track Down a Production Dump

Problem: On Monday morning the finance team reports an ABAP dump (transaction code shown in the error). It only happens "sometimes," and no one knows what changed.

Root Cause Analysis — a structured debugging workflow:

  1. Read the statistical information at the end of the dump: program name, include, line number, and call stack — it tells you exactly where the error occurred.
  2. Check recent transport entries (SE03 / SE09): 9 out of 10 times the bug was introduced by a transport last week.
  3. Reproduce with the same SELECTION parameters the user used. Intermittent dumps are often data-dependent (a missing customer master, an empty range, a division by zero on a blank quantity).
  4. Run the code checker (SLIN) and the extended program check — they flag most divide-by-zero and range issues statically.
  5. Add defensive code at the failing point and retest with the original data.
Common dump you will meet — division by zero:
IF ls_data-quantity = 0.           " Guard first!
  WRITE: / 'Skip zero quantity'.
ELSE.
  lv_price_per_unit = ls_data-amount / ls_data-quantity.
  IF lv_price_per_unit IS INITIAL.  " Overflow check
    WRITE: / 'Overflow detected'.
  ENDIF.
ENDIF.
Key lesson: Dumps carry a call stack — the dump is a map, not a mystery. Track transport history to find "what changed."

Case Study 8: Spaghetti Report Becomes a Maintainable Object-Oriented Program

Problem: A 2,000-line legacy report mixes database access, business rules, and screen logic in one long START-OF-SELECTION. Any change breaks something else.

Solution — refactor into three layers:

CLASS lcl_order_service DEFINITION.        " Data layer
  PUBLIC SECTION.
    METHODS: get_orders
      IMPORTING it_seldate TYPE range_tab_seldate
                iv_status   TYPE c
      RETURNING VALUE(rt_orders) TYPE tab_orders.
ENDCLASS.

CLASS lcl_order_processor DEFINITION.      " Business layer
  PUBLIC SECTION.
    METHODS: process CHANGING ct_orders TYPE tab_orders.
ENDCLASS.

CLASS lcl_order_report DEFINITION.       " Presentation layer
  PUBLIC SECTION.
    METHODS: display IMPORTING it_orders TYPE tab_orders.
ENDCLASS.

* --- Wiring in START-OF-SELECTION stays tiny ---
DATA: lo_svc  TYPE REF TO lcl_order_service,
      lo_bus  TYPE REF TO lcl_order_processor,
      lo_alv  TYPE REF TO lcl_order_report,
      lt_orders TYPE tab_orders.

CREATE OBJECT: lo_svc, lo_bus, lo_alv.

lt_orders = lo_svc->get_orders( it_seldate = s_date[] iv_status = p_stat ).
lo_bus->process( CHANGING ct_orders = lt_orders ).
lo_alv->display( lt_orders ).
Key lesson: Splitting data / business / presentation lets you test each piece independently and change one without breaking the other two.

Debugger Quick Hacks

  • Breakpoints — /H in the transaction code field activates the debugger on the next line of code executed.
  • Dynamic breakpoints — set inside the editor: double-click the line number, or use toolbar button.
  • Watchpoints — stop when a specific variable changes value (right-click variable in debugger → Create Watchpoint).
  • Sneaky print — temporary WRITE or BREAK-POINT statements where you suspect the bug.
  • Trace SQL — run ST05 with SQL trace on, execute the report, view the generated statements and their row counts.

Tips for Beginners

  • Follow naming conventions — lv_ for local variables, lt_ for local tables, gs_ for global structures, c_ for constants.
  • Check sy-subrc after every database and table operation. Ignoring it leads to phantom bugs.
  • Prefer SELECT ... INTO TABLE over selecting in loops — huge performance win.
  • Use field symbols (ASSIGNING) instead of work areas for large tables.
  • Use ALV instead of WRITE for reports — users get export, sorting, and filters for free.
  • Comment your code — * for full-line comments, " for inline comments. Future-you will thank yourself.
  • Create message classes in SE91 instead of hard-coding message text.
  • Test with edge cases — empty tables, single records, large volumes, special characters.
  • Use code checking — run transaction SLIN or use the check button inside SE38 before activating.
  • Work in a development client — never test creating/deleting data directly on production.
